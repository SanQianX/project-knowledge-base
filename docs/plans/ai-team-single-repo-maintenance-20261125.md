# AI 团队单仓库维护一期执行计划

知识库任务 `task_a4f2f3311b852dcd8680`。在现有 AI 团队下给一个已登记的 Git 仓库配置维护成员。成员的提示词和记忆组合引用由团队设置提供。检查规则、修复方式、格式和文档处理留给操作者登记的外部工具。

## 一期操作路径

1. 操作者在 Workflow 数据目录登记一个项目、目标分支和本地工具。每条命令使用绝对可执行文件路径和参数数组。网页只选择已登记工具。
2. 在「AI 团队 → 仓库维护」新建任务，选成员、工具和触发方式。Review 可选目标分支提交触发，格式和文档可分别选每日时间。时间使用北京时间。手动运行也有独立入口。
3. 开发期间可标记仓库占用。系统还会检查原工作区的未提交改动和进行中的 Git 操作。条件解除后按队列继续。维护工具在可复用的独立 worktree 中执行。
4. 查看触发、检查、修复、复查、错误和候选提交。默认将维护提交保存在本机，供人工检查或 cherry-pick。只有本机登记和任务均启用推送，且远端仍是本轮基线时，才尝试普通快进推送。

## 边界与恢复

- 一期的工具接口是本地 CLI。已有 MCP 工具可通过操作者提供的本地适配器调用。成员上下文随调用传入，记忆正文仍由知识引擎及其授权链处理。
- 维护 worktree 隔离当前工作区文件。它共享 Git 对象和引用；本机登记意味着操作者授权这些工具以当前用户身份运行。脚本应同步执行并遵守传入的工作目录。
- 失败的脏 worktree 保留，阻塞后续写入。中断后先检查候选提交、远端和残留进程，再在页面解除保护。恢复操作不重放已领取的写操作。
- 测试使用合成仓库、合成成员、独立安装与独立本地裸远端。当前正在运行的日常安装照常使用。
