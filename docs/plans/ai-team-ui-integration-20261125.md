任务 `task_473d7e2a9e111dcf820e`，2026-11-25。

## 界面设计

首页仍由知识库的「AI 团队」入口打开。嵌入页沿用知识库的背景、边框、强调色和深浅主题。内页保留「任务」和「团队设置」，并用真实团队名称作为当前位置。任务页继续采用任务列表和详情的左右结构，窄屏时按列表、详情顺序进入。

团队设置先显示成员和项目，再提供接入诊断。成员可新建或编辑名称、角色、提示词、模型和记忆组合引用。组合选择使用知识库的现有目录。项目选择使用已登记的项目名称，切换项目后按实际设置填写 Leader、开发成员和 Reviewer。保存带上当前已读版本；版本冲突明确提示重新加载。

维护自动化的工具登记、日程、条件触发和 worktree 状态保留在可点击的设计预览中，用示例展示。正式工作台根据 Workflow 现有接口呈现真实状态。自动化执行、后端工具调用、Git 写回需要独立产品阶段。

## 执行顺序

1. 核对运行基线和渲染接口。Workflow 使用与日用版对应的 `0.2.2` 和上游 `d608a60`。知识库使用当前 `main` 的同源 `/workflow-ui/` 入口。
2. 在壳层发送实时主题和颜色，在 Workflow 页面校验来源并应用。保留未发送颜色的旧壳兼容路径。
3. 重做团队设置的成员区域和项目区域。成员调用 Workflow 的 `members` API，项目使用知识库项目目录和 Workflow 配置接口。保留可回读的记忆组合 ID 和项目配置版本。任务详情、代码审查和验收继续使用原接口。
4. 同步修改可操作的设计预览，用示例数据检查提交触发、每日格式与文档任务和仓库排队。
5. 从独立测试目录启动应用和 Workflow，用合成项目运行浏览器集成、契约、模块回归和打包检查，保存实际结果。最后复查日用实例的服务身份和团队，登记任务证据。
