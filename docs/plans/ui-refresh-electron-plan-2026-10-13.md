# 加载与刷新修复，再交付 npm Electron 桌面版

保存日期：2026-10-13。

状态（2026-10-15）：网页部分已完成源码、最终候选及正式 npm 5.0.17 安装版验收，官方 latest 已更新为 5.0.17。Electron 部分按用户要求延期，不在本次交付范围。实际通过项、首次失败与未覆盖环境见 `../release-5.0.17-acceptance.md`，不能以本计划代替验收结果。

## 一、目标与实施顺序

先修复网页版本，再复用同一套页面和后台进行 Electron 化。Electron 不是卡顿修复方案，网页验收通过后才进入桌面阶段。

当前代码已发现三个明确风险：

- 外壳等待多个接口全部完成，慢模块拖延其他页面。
- Workbench 的 Agent 探测使用同步进程调用，可能阻塞后台；页面未处理外壳的可见性刷新消息。
- 引擎启动逐个项目接线，一个项目失败会使全局一直显示“待恢复”。

实施前记录实际运行版本、请求耗时、后台事件循环延迟、页面长任务和连接数量。保留现有未提交改动、项目、知识、配置及历史，不通过清空数据制造通过结果。

## 二、网页加载与刷新改造

### 页面不再整体等待

- 导航与按钮先绑定，各区域独立加载。项目登记、模块健康、引擎状态不再互相阻塞首屏。
- 明确区分“加载中”“暂无数据”“服务不可用”和“正在刷新”；请求失败保留上次有效内容，不误显示没有项目或没有 Agent。
- 普通状态读取设置 3 秒超时；目录选择、模型执行和流式连接使用独立超时策略。
- iframe 只初始化一次。切页、主题和项目切换不重新设置地址，不清空草稿、历史、模型选择或进行中的消息。
- 列表与详情分开读取，运行记录分页展示；不随每次状态刷新传输完整提交证据。

### Agent 发现改为异步

- CLI 探测改为异步子进程，最多两个并发，每个探测最长 5 秒；一次扫描总体预算 12 秒。
- 保留现有损坏 npm shim、原生安装路径及认证诊断能力。
- `GET /agents` 保留兼容结果，增加扫描状态、更新时间和代次信息。
- 新增 `POST /agents/refresh`，启动或复用扫描；手动重新扫描必须绕过旧缓存。
- 扫描期间显示上次结果及“正在检查”，不能把超时或读取失败当成“未安装”。
- 进入开始工作、打开 Agent 设置、窗口重新获得焦点时执行合并刷新；后台执行任务不依赖其他 Agent 的探测结果。

### 统一刷新与实时连接

- Workbench 补齐 `kb:visibility`、`kb:refresh`，增加刷新回执；携带项目、会话及关联标识，忽略迟到响应。
- 页面恢复可见或网络恢复后，先读取当前快照，再按游标续接事件；保留成熟的流式消息处理与会话恢复逻辑。
- 外壳新增同源 `/api/live` WebSocket，复用已有依赖，合并引擎进度、工作台消息和日志订阅。嵌入 Workbench 通过现有可注入传输接口接入，不重新实现消息渲染。
- 独立模块原有 SSE 接口保留。订阅按需开启、取消并释放上游连接；重连具有退避、游标及有界缓冲。
- 校验来源、发送窗口和允许订阅的路由，禁止任意代理地址及凭据进入浏览器消息。

### 引擎恢复不再拖住整个产品

- 模块就绪或重启后立即触发合并接线，不仅等待固定轮询。
- 配置同步使用单任务合并，配置未变化时不重复下发。
- 将服务连接状态与项目接线状态分开显示；失败项目独立重试，正常项目不反复重新登记。
- 只有完成鉴权、配置及安全接线的项目才能执行维护。不能为了消除“待恢复”文案而提前启用写入。
- “服务启动中”“项目接线失败”“索引待修复”分别展示，并提供真实原因和日志关联。

## 三、Electron 与 npm 分发

### 分发方式

新增独立包 `@sanqianx/project-knowledge-desktop`，保留现有网页包，避免网页用户被迫下载 Electron。计划提供：

```powershell
npm install -g @sanqianx/project-knowledge-desktop@latest
project-knowledge-desktop
project-knowledge-desktop status
project-knowledge-desktop stop
```

以上是计划中的命令，不表示桌面包已发布。

桌面包锁定已经验收的核心包与 Electron 精确版本，不使用 `file:..`、兄弟仓库或开发源码兜底。

可以通过 npm 安装并启动，不需要为了 npm 分发先购买代码签名证书。但 Electron 运行文件可能另行下载，npm registry 设置不保证覆盖这次下载；需提供下载失败、代理和缓存诊断。[Electron 安装说明](https://www.electronjs.org/docs/latest/tutorial/installation)

正式发布 Windows/macOS 安装程序时，代码签名属于另一项工作；macOS 正式分发还涉及 Apple 公证。本轮不做签名安装包和应用内自动更新，也不要求用户关闭系统安全检查。[Electron 签名说明](https://www.electronjs.org/docs/latest/tutorial/code-signing)

### 桌面行为

- 直接使用修复后的产品 HTML/CSS/JavaScript，页面外观与网页一致。
- 先显示可交互的启动窗口，再等待后台连接；连接失败展示诊断及重试，不长期空白。
- 复用现有实例身份校验和数据目录，不创建第二套项目登记或知识库。
- 兼容版本的后台直接复用；版本不匹配时明确提示，不暗中启动第二个写入者。
- 关闭窗口隐藏到托盘，知识维护继续运行；明确退出时停止桌面自身启动的后台，复用的网页后台不擅自停止。
- `stop` 使用现有受管实例的安全退出协议；停止后桌面不能自动重新拉起。
- 保持隔离、安全沙箱及最小 IPC，不向页面暴露 Node 或凭据。
- 原生模块按操作系统和架构选择，移除“仅保留 Windows x64”的跨平台假设。知识及向量目录保持原配置不变。
- 升级仍采用 npm 明确安装；显示桌面、核心及模块实际版本。

## 四、测试与验收门禁

只测试正常桌面视口。确定性替身测试、真实模型测试和 npm 安装版测试分别记录。

| 场景 | 必须通过 |
|---|---|
| 冷启动与模块离线 | 导航可用，各区域独立反馈；慢模块不造成全页空白 |
| Agent 发现 | 安装、卸载、损坏入口、慢 CLI、认证变化均正确刷新；扫描不阻塞消息与健康接口 |
| 开始工作 | 真实发送、增量消息、中止、历史、草稿和权限处理正确；离开再回来自动恢复 |
| 项目切换 | A→B→A 及迟到响应不串项目；后台 A 任务继续 |
| 实时恢复 | 断网、后台重启、隐藏后恢复、打开八个标签页不挂起；事件不丢失、不重复累积订阅 |
| 知识维护 | 真实提交触发维护，文件晋升、索引与检索成功，页面无需手动刷新 |
| Electron 生命周期 | 重复启动、网页与桌面共存、隐藏、退出、stop、版本冲突不产生遗留实例或双写 |
| npm 安装 | 独立缓存和 prefix 下载，验证包内资源、精确依赖、原生模块及实际运行版本 |

性能门禁：

- 服务已监听后，首屏导航与静态控件 1 秒内可用；切页反馈 P95 不超过 200 毫秒。
- 健康环境下，已有页面的状态更新 P95 不超过 1 秒。
- 注入慢 Agent 探测时，轻量健康接口 P95 不超过 500 毫秒。
- 正常实时事件到可见更新不超过 1 秒；模型生成耗时不计入此项。
- 重复切页和项目切换后，连接、监听器及内存不持续增长。
- 使用多项目、千条运行记录的隔离数据验证分页与刷新，不能只测试空数据库。

真实链路至少包含一次工作台流式任务、一次提交维护及一次检索刚生成知识的后续任务。缺少模型条件时标记未完成，不计为通过。

## 五、发布与默认边界

1. 先交付网页修复候选包，从官方 npm 下载验收，再发布正式网页版本。
2. 网页通过后交付 Electron 候选包，完成 Windows 本机 npm 安装验收后才更新桌面包 `latest`。
3. 本轮默认 Windows x64、Node 22/24；引擎继续 CommonJS、零新增 npm 依赖。
4. macOS 保留平台适配及测试入口。由于目前没有 Mac，真实安装、原生模块、目录选择和生命周期验收列为未完成门禁，不宣称已经正式支持。
5. 交付修复提交、延迟对比、实际版本与 integrity、桌面截图及“操作→后台→文件/索引→界面”的证据。只清理本轮可确认归属的临时测试数据。
