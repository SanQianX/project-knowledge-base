# AI 团队成员工具开发指南

适用于提供 Agent 维护计划的知识库版本。

这份指南讲的是：AI 团队的成员要用一个工具去做事时，这个工具怎么写、怎么登记、怎么试。页面上「登记工具」旁边的「怎么写工具？」是它的精简版。

## 自动维护是什么

维护计划可以在提交后、每天指定时间或手动触发。每次运行会把计划的提示词交给负责的 Agent，由它调用已登记的本机检查工具。

### 由 Review Agent 执行

在「团队设置」为负责成员选择工作台里的模型。在「自动维护」新建计划，选择负责的 Agent 和本机检查工具，再填写提示词和触发条件。旧的直接工具计划会显示「待配置 Agent」，编辑并保存后可以运行。

「允许 Agent 修复」授权成员在维护 worktree 内小范围修改本次基线提交改动的文本文件。存在活动开发任务、改动重叠、Git 操作或可写范围不明时，运行仍可在已提交版本上做只读检查。Agent 的读取限于隔离 worktree 中的 Git 跟踪文本文件，配置的模型会收到它读取的代码和检查输出。

补丁通过检查后以候选提交交付。目标分支在运行期间前进时，运行器会尝试在该分支最新提交上应用同一补丁，再交给同一个 Agent 请求复检。详情里能核对首次检查的 SHA、候选补丁的复检 SHA、每次真实工具输出，以及只读原因。

## 一个团队管多个仓库

一个 Reviewer 成员要盯几个仓库，不需要每个仓库各建一套：

- **仓库**：一个知识库最多登记 20 个，一个项目登记一个目录。在「自动维护」页点「登记仓库」，一次可以勾选多个项目。
- **工具**：最多 12 个，所有仓库共用。登记一次，参数里写占位符（见下一节），哪个仓库运行就换成哪个仓库的路径。
- **维护计划**：最多 12 份，每份绑定一个或多个仓库。新建时已登记的仓库默认勾选；团队挂载了但还没登记的项目也在列表里，勾上以后保存时自动登记。

到了条件，计划在它绑定的每个仓库各运行一次：

- **提交触发只跑提交所在的那个仓库。** 在甲仓库提交，只检查甲仓库，即使计划同时绑定着乙仓库。
- **每天触发按「计划 × 仓库」各记一次日期。**
- **同一个仓库里的任务排队，不同仓库同时跑**，同时最多 3 个。
- **占用和保护都是针对一个仓库的。** 甲仓库正在开发，不影响乙仓库运行；甲仓库的维护工作区出了问题，也只有甲仓库停下。

删除仓库前要先在维护计划里去掉它，并且等它的任务结束。删除后它的运行记录归档，页面不再显示，但不会丢。

## 成员和工具的关系

| 成员在哪条线上做事 | 用的是什么 |
| --- | --- |
| 任务：Leader 规划，开发成员实现，审查成员审查 | 知识库自带的检查器和模型，不是这里登记的工具 |
| 自动维护 | 负责 Agent 调用登记的本机检查工具 |

登记的工具只在维护计划里被使用。计划运行时，模块把负责成员的信息随输入传给工具。

成员的「模型」来自工作台中已启用、已配置凭据的档案。自动维护的 Review Agent 用该档案和模型运行。团队任务指定了 Reviewer 时，成员的模型须与项目的受信审查配置一致。

## 工具是什么

一个能在本机直接运行的程序。Node、Python、PowerShell 脚本或 exe 都可以。模块按你登记的「程序路径 + 参数」启动它，不经过 shell。

工具不碰你正在开发的目录。模块先为仓库建一个独立的维护工作目录（一个 Git worktree），工具在里面运行，工作目录就是仓库根，以你的系统用户身份执行。每个仓库有自己的维护工作目录。

本地项目的维护检出放在已配置的知识保存目录下。路径是 `<知识保存目录>/.ai-team/worktrees/<仓库ID>`，其中 `.ai-team` 会被知识索引跳过。已有仓库在保存设置或点击「运行一次」时取得这个位置。旧 worktree 和其中的改动可在仓库的「工作目录」中查到。团队知识库继续使用运行数据目录。

批量登记时只选择项目。各仓库在手动或每日运行时读取本地当前分支的提交，提交触发使用事件里的分支和 SHA。需要长期检查指定分支时，在「仓库与工具」中修改仓库的固定分支。清空固定分支后，仓库恢复跟随当前分支。

## 参数里的占位符

工具是所有仓库共用的，所以参数里不写死某一个仓库的路径。参数里**单独一项**写成下面三种之一，运行时换成当前仓库的值：

| 占位符 | 换成 |
| --- | --- |
| `{repo}` | 这个仓库自己的目录（你开发用的那个） |
| `{workspace}` | 这个仓库的维护工作目录，也就是工具的当前工作目录 |
| `{branch}` | 本次运行使用的分支 |

例如工具要用仓库里装好的依赖：程序路径填 `node.exe`，参数一行是脚本路径，一行是 `check`，一行是 `{repo}`。只有整个参数等于占位符时才替换，写在一段文字中间的不替换。

## 模块给工具什么

标准输入里一行 JSON，以换行结束：

```json
{
  "schema": "ai-team-maintenance/v1",
  "projectId": "…", "jobId": "…", "runId": "…",
  "workspace": "维护工作目录", "repoPath": "仓库自己的目录", "branch": "main",
  "baseSha": "起始提交",
  "trigger": { "kind": "commit", "commitSha": "…" },
  "member": { "memberId": "…", "name": "维护 Agent",
              "instructions": "成员的职责提示词", "memoryGroupIds": [] },
  "phase": "check", "attempt": 0, "findings": null
}
```

| 字段 | 含义 |
| --- | --- |
| `schema` | 固定是 `ai-team-maintenance/v1` |
| `projectId`、`jobId`、`runId` | 知识库项目、维护计划和这次运行 |
| `workspace` | 维护工作目录，也就是当前工作目录 |
| `repoPath` | 这个仓库自己的目录，不是维护工作目录。要用仓库里装好的依赖时用它 |
| `branch` | 本次运行使用的分支 |
| `baseSha` | 本轮的起始提交。提交触发时是那次提交，每日和手动触发时是目标分支的最新提交 |
| `trigger` | `manual`、`commit`（带 `commitSha`）或 `daily`（带日期、时间和时区） |
| `member` | 负责成员：`memberId`、`name`、`instructions`、`memoryGroupIds` |
| `phase` | `check` |
| `attempt` | 检查次数，从 0 开始 |

## 检查退出码

| 退出码 | 结论 |
| --- | --- |
| 0 | 通过 |
| 1 | 有问题，Agent 可在授权范围内修复并再次请求检查 |
| 其他 | 工具运行失败，可在详情查看输出 |

## 必须遵守

- **程序路径**：绝对路径，并且已经存在。Windows 上不能填 `.cmd` 或 `.bat`，要填 `node.exe` 的路径，脚本写在参数里，一行一个。
- **同步跑完就退出**：默认 120 秒超时，最长可设 1800 秒。超时后这次运行会中断并进入保护状态。
- **不要动 Git**：不提交，不切换提交。每一步之后模块会核对当前提交没变，提交由模块来做。
- **只读工作目录**。每路输出最多保留 64 KB，页面只显示前 8 KB，结论要放在最前面。
- **环境变量只传白名单**（PATH、HOME、USERPROFILE、APPDATA、LOCALAPPDATA、TEMP 等）：API 密钥之类的传不进去，工具要自己从文件读凭据。
- **工具可以放在仓库之外**。放在被检查仓库里的工具，先提交再使用。

## 用上成员的信息

检查工具从输入的 `member` 字段读取名字、职责提示词和记忆组合 ID。工作台使用负责成员配置的模型，工作流负责限制文件操作。

所以让工具按成员定制，就是工具自己使用 `member.instructions`，例如把职责提示词当作规则去调用模型。记忆正文目前工具取不到。

## 示例一　检查行尾空格

```js
// Run with node.exe trailing.js
'use strict';
const fs = require('node:fs');
JSON.parse(fs.readFileSync(0, 'utf8'));
const markdownFiles = fs.readdirSync('.').filter(name => name.endsWith('.md'));
const filesWithTrailingWhitespace = markdownFiles.filter(name => /[ \t]+$/m.test(fs.readFileSync(name, 'utf8')));
if (filesWithTrailingWhitespace.length) {
  console.log(JSON.stringify({ files: filesWithTrailingWhitespace }));
  process.exitCode = 1;
}
```

在「登记工具」中，程序路径填 `node.exe` 的完整路径，参数填 `trailing.js` 的路径。

## 例子二：按成员的职责提示词调用模型

这是一个适配器的骨架，省略了调用模型的部分。它说明三件事：凭据从文件读，职责提示词取自成员，调用失败要和「有问题」区分开。

```js
// review.js — 用法：node.exe review.js check
'use strict';
const fs = require('node:fs');
const path = require('node:path');
const input = JSON.parse(fs.readFileSync(0, 'utf8'));
if (process.argv[2] !== 'check') process.exit(2); // 这个工具只做检查

// 凭据从文件读：环境变量只传 PATH、HOME、APPDATA 等几项，API 密钥传不进来。
const key = fs.readFileSync(path.join(process.env.USERPROFILE, '.my-tool', 'key'), 'utf8').trim();
const request = [
  input.member.instructions, // 成员的职责提示词，例如「只关注接口文档与实现是否一致」
  '检查这个目录：' + input.workspace,
  '发现问题时输出一行 JSON：{"path":"相对路径","expected":"应当怎样"}；没有问题时什么都不输出。',
].join('\n\n');

// 用 request 和 key 调用你选的模型，然后按结论退出：
//   有问题     console.log(JSON.stringify({ path, expected })); process.exit(1)
//   没有问题   process.exit(0)
//   调用失败   process.exit(2)   算工具自身故障，不会被当成「有问题」
```

## 登记与试运行

1. 把工具放在仓库之外的任意目录。
2. 先当普通命令行程序写好，手工喂一段 JSON 跑通。
3. 打开「AI 团队 → 自动维护」。还没登记仓库的，先选项目登记仓库，可以一次选多个。
4. 展开「仓库与工具」并点「登记工具」，填名称、程序路径和参数。保存时会检查程序路径存在。
5. 点「新建计划」，选 Agent、检查工具和目标仓库，填写执行提示词。首次试运行可选手动触发。
6. 对计划点「运行一次」，它绑定的每个仓库各运行一次。在运行详情里看每一轮的退出码和输出，运行记录按仓库列出。
7. 根据需要调整触发条件或勾选「允许 Agent 修复」。

## 常见问题

**运行详情显示「只读」。**
检查仍基于已提交的代码。活动开发任务、Git 操作或与未提交改动重叠时，Agent 不能修复。需要暂停该仓库的队列时，可在「仓库与工具」标记开发占用。

**校验维护 worktree 时提示找不到文件。**
运行详情在可用时显示找不到的具体路径。「仓库与工具」可以查看工作目录和保护状态。核对目录和 Git 关联后解除保护，再点「运行一次」。

**在乙仓库提交了，甲仓库没有反应。**
提交触发只运行提交所在的那个仓库。这是有意的：乙仓库的提交改不到甲仓库的代码。想让甲仓库也跑一遍，对计划点「运行一次」。

**仓库删不掉。**
提示里会说明原因：仍有维护计划绑定着它（提示里列出计划名），或者它还有排队、运行中的任务。先在这些计划里去掉它，或者等任务结束。

**运行「未通过」。**
打开运行详情看原因。「仍有检查未通过项」表示检查工具报告了问题。「检查命令执行失败」时可以查看退出码和工具输出。

**改动在哪里？**
运行详情里的「候选提交」是修复小补丁的提交号。可以用 `git show <提交号>` 查看，再用 `git cherry-pick <提交号>` 合入目标分支。

**工具能拿到 API 密钥吗？**
不能从环境变量拿。模块只传 PATH、HOME、USERPROFILE、APPDATA、LOCALAPPDATA、TEMP 等几项。工具自己从文件读凭据，放在你的用户目录下。

**为什么不能填 .cmd 或 .bat？**
模块不经 shell 启动程序，而 Windows 上这两种脚本必须经 shell。填 `node.exe` 的完整路径，把脚本路径写在参数里。

**能登记几个？**
一个知识库最多登记 20 个仓库、12 个工具、12 份维护计划。工具所有仓库共用；一份计划可以绑定多个仓库；一个项目登记一个目录。

## 现在没有的

- MCP 工具直接接入。已有的 MCP 工具可以由你写一个本地适配器来调用。
- 工具读取记忆正文。成员的记忆组合 ID 会传给工具，正文目前取不到。
