# v5 从头开始

本版按用户确认不再迁移以前的知识库数据。旧文件留在原位置，但新版不会读取它们；没有对用户代码仓库或旧知识目录执行删除。

## 更新

```bash
project-knowledge stop
npm install -g @sanqianx/project-knowledge@latest --registry=https://registry.npmjs.org/
project-knowledge-integrations update
project-knowledge
```

需要 Node ≥22 和 Git。默认使用 `~/.project-knowledge-v5`，四模块的托管数据也在此目录内。若环境变量 `KB_DATA_DIR` 仍指向旧目录，请取消该设置或改为新的空目录。不要把旧 `projects.json`、设置或引擎状态复制进新目录。

在“系统状态”重新配置模型与后台默认模型、embedding 和知识根目录，然后在“领域与项目”导入代码目录及新的空知识目录。原代码目录无需移动。若残留旧知识库托管 Hook，导入预检会要求明确确认替换；不会覆盖第三方 Hook。导入建立 HEAD 基线，不分析已有历史。

如果模块是自己独立启动的旧进程，请在它原来的终端中停止后重启新版外壳。外壳不会擅自杀死其他服务；版本或运行期鉴权不一致时显示具体连接阶段，不接管旧服务数据。

## 解绑与恢复

“解绑并保留数据”从项目列表移除登记、取消未开始任务并卸下本项目托管 Hook，保留代码、知识、会话及证据。实际分析或索引写入尚未结束时仍禁止解绑，防止丢失写入状态。队列本身不再被当成正在运行。

删除的是旧版本兼容路径，不是新版的故障恢复能力：v5 自身的重启恢复、提交去重、并发限制、失败重试和索引修复仍有效。`upgrade-recovery` 不再存在。

## 回归范围

旧格式迁移专用测试随旧实现删除，替换为旧目录拒绝且原字节不变、空状态启动、连接失败诊断与恢复、旧托管 Hook 的显式替换和回滚测试。真实提交链路继续由引擎 Git/Hook/journal/晋升/索引回归和五服务网页回归覆盖。模型替身和真实模型的结果分开记录；旧版本真实调用记录不计为本版通过。
