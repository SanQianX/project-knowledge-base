# Agent Terminal 模块实施计划(目标仓库:D:\SanQian.Xu\claude-ai-workbench)

## 目标

把 claude-ai-workbench 从「单 Claude Code 终端 SDK」升级为「通用 Agent 终端模块」:多项目工作区、自定义模型供应商管理、四家 Agent(Claude Code / Codex / OpenCode / ZCode)发现与接入、ZCode 风格整页 UI。模块独立启动、独立测试、全新数据(不迁移旧 profiles/会话)。project-knowledge-base 本轮不动。

## 关键决策(已与用户对齐)

1. **新页面 `apps/agent-terminal/`,路由 `/agent-terminal/`**;旧 `/terminal/`、`/profile-settings/` 原样保留。
2. **四家 Agent 全部实现驱动**并在本机做真实连接测试;ClaudeCode 驱动用 MiniMax Anthropic 兼容端点(凭据只经环境变量/凭据接口注入,不写入文件;对话中贴过的 key 建议轮换)。
3. **全新开始**:新数据目录 `~/.agent-terminal`(env `AGENT_TERMINAL_DATA_DIR` 可覆盖),旧 `~/.claude-ai-workbench` 不动。
4. 交互/视觉基线 = `docs/agent-terminal-ui-preview.html`(已冻结):侧栏多项目+归档+移除、扁平黑消息流、底部命令栏(模型下拉含"管理模型"、推理力度、上下文容量气泡、权限模式)、设置页(供应商/Agent 发现/嵌入说明)。

## 架构方案

**复用现状**:`WorkbenchService` 的 runner 注入缝、`claude-cli-runner`(SDK 调用/权限链/会话持久化/事件流全齐)包装为 ClaudeCodeDriver,不重写;`ProfileStore` 凭据隔离(credentials.v1.json + 掩码)直接作为供应商存储层;`packages/client` 的 REST/SSE 封装供新 UI 使用。

**新增**:
- `packages/contracts`:AGENTS 注册表 + 能力矩阵 + normalizeProject + profile 扩展(models.list、generationParams)
- `packages/server/lib/project-store.js`:projects.v1.json(原子写 0o600)
- `packages/server/lib/agent-discovery.js`:四家 CLI 探测(存在性/版本/登录态)
- `packages/server/lib/agent-registry.js`:agentId → driver 路由
- `packages/server/lib/drivers/{claude-code,codex,opencode,zcode}.js`:claude-code 包装现有 runner(profile 注入,支持 MiniMax anthropic 兼容端点 + effort→thinking budget);其余三家 CLI 子进程驱动,每个先本机探测真实接口(`codex --help` / `opencode --help` / `zcode --help`)再实现事件归一化;能力矩阵诚实声明(Codex exec 模式无交互权限卡等如实降级,UI 自动隐藏)
- `apps/agent-terminal/`:整页 UI(vanilla 零构建,server 托管,复用 packages/client)
- `packages/server/bin/agent-terminal-server.js`:独立启动入口(新数据目录)
- API 增量(前缀不变,全部向后兼容):projects CRUD、GET /agents、会话带 agentId/projectId、归档/恢复、GET /sessions/:id/context-usage;openapi.yaml 同步

## 实施波次(每波结束 npm test 全绿)

**Wave 1 — 数据模型与 API**:contracts 扩展;project-store + 路由 + client 方法;fake-runner integration 测试(projects CRUD、会话归属、归档/恢复、移除)。

**Wave 2 — 驱动层**:registry + discovery + 四个 driver(ClaudeCode 先行;外部 driver 探测前置);effort 槽位;context-usage 端点;fake 双驱动路由测试。

**Wave 3 — ZCode 风格 UI**:port 预览页;侧栏/消息流/命令栏/容量气泡/设置页全套交互;真实浏览器对照预览验收。

**Wave 4 — 真实连接测试 + 发布**:tests/real 四家 env 门控测试(起会话→发一条→断言事件→清理);`npm run start:agent-terminal`;文档更新;五包同步 0.3.0;`npm run verify` + sdk:pack 全绿(pack-sdk 的 runtimeFiles 纳入新 driver)。

## 风险与守门

- 不破坏现有端点族、旧页面、contract 测试(additive only)。
- 外部 driver 以本机探测结果为准,不支持的 capability 如实降级。
- 凭据只走 credential 接口/env,不入库不入码。

## 本轮不做(后续立项)

postMessage 嵌入桥、headless 单轮模式(project-knowledge 收敛)、事件前缀改名。
