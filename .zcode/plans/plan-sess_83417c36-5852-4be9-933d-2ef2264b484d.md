# 知识注入对齐 ZCode memory 模式：会话一次索引 + 面包屑提醒 + 记忆实时 diff

## Context（为什么改）

UserPromptSubmit hook 每条用户消息全量注入知识上下文（上限 8000 字符）并永久留在会话历史，O(n) 累积（30 条消息 100–240 KB，实测 16 万 token 会话的重要成因）；已确认记忆每条消息全量注入（`context.js:63-77`）；安全声明/仲裁规则每次重复（`context.js:12-13`）；空结果也注入提示语（`context-hook.cjs:54-56`）。每消息全量注入加速上下文膨胀→更早触发压缩→旧注入被摘要丢失——"用注入对冲遗忘"反而制造遗忘。附带症状：摘录按关键词而非当前问题相关性匹配（`retrieval-ranking.js:112` 单 bigram 命中即入围），单条正文 1200 字符不截断（`context.js:91`）。

**方案**（参考 ZCode memory 的"索引+懒加载、成本恒定"）：
- **会话一次索引**——首条用户消息注入一次紧凑索引（适用记忆全文 + 知识条目标题清单 + 声明，仅此一次）；正文摘录从此不出现在注入层，相关性与摘录过长问题在注入侧消失。
- **对冲遗忘三件套**：①面包屑——当前问题与某条知识强相关时注入一行指针（问哪条提醒哪条，指回索引与 MCP）；②>30 轮重发仅标题索引（对冲上下文压缩）；③MCP 按需取数与会话长度无关，最终兜底。
- **长期记忆实时 diff**：引擎每条消息对照实时记忆库与会话注册表，新增/变更的记忆全文重注入一次、删除的记忆发一行移除提示——会话中途（含其他客户端/Workbench）确认的新记忆下一条消息即可见。

架构事实：装配/会话逻辑在 npm 包 `@sanqianx/ai-coding-knowledge-engine@0.2.7-rc.12`（源码仓 `D:\SanQian.Xu\knowledge-engine`，main 开发，AGENTS.md 禁止 vendoring 回本仓库）；引擎常驻且已按 sessionKey 维护状态（`context.js:43,118-126`）；`prepare()` 每次实时读适用记忆（`context.js:66`），`memoryStatus: pending` 防陈旧机制原样保留；hook 请求已带 `sessionId`（`context-hook.cjs:44`）。会话锚点用首条 UserPromptSubmit（四客户端统一）。MCP 检索路径（search/get）排序与准入**完全不动**——金标准验证的对象。

## 改动一：引擎仓库 `D:\SanQian.Xu\knowledge-engine`（main）

### 1. 会话索引装配 — `src/context.js`
- 会话注册表 `sessionIndexes`：Map<sessionKey, { at, turnSeq, indexedTitles, memoryHashes, breadcrumbAt }>，LRU 500 会话、TTL 24h（重启丢失 → 下一条消息重注一次索引，无害）。
- **首条消息（未注册）**：注入 `HEADER + memories + facts索引 + FOOTER`：适用已确认记忆全文（预算 ~1500）；facts 标题清单（goal → architecture → modules → 近期 changes，一行 `- 标题 (entryId)`，预算 ~1200，有余再列 domain 参考标题，仍只列标题）；**无正文摘录**；FOOTER 指引详情走 `project_knowledge_search/get`。总预算 ~3000（8000 硬上限保留），常量收拢接 policy。
- **后续消息——三个通道，其余静默**：
  - **记忆 delta（全文）**：实时适用记忆集对比 `memoryHashes`——新增/变更的记忆**全文重注入一次**（单条 ≤2000，预算 ~2000，前缀"记忆更新"）；删除 → 一行 `记忆已移除：<标题/id>`；pending 未同步条目跳过。
  - **面包屑（一行指针）**：当前查询与条目强相关（实词命中 wordAnchors≥1 或 exact 身份信号或已校准向量命中，**仅 bigram 不触发**）→ `- 相关知识：标题 (entryId)`，覆盖新条目与已索引条目，不带正文。≤3 行/消息，同 entryKey 10 轮冷却。
  - **索引刷新**（默认开）：距上次索引 >30 轮重发仅标题索引。
- **响应契约向后兼容**：`status` 枚举不变（ready/empty/file-fallback）；新增可选字段 `injectionKind: 'index'|'memory-delta'|'breadcrumb'|'refresh'` 与 `sessionIndexedCount`；诊断日志加 injectionKind。

### 2. 支撑改动
- `src/retrieval-ranking.js`：anchor 计数拆 `wordAnchors`（weight-1 实词）/`gramAnchors`（weight-0.2 bigram），仅用于面包屑门槛；search 路径准入保持 `wordAnchors+gramAnchors>0`（与今日 `lexicalAnchors>0` 等价，排序不变）。`VERSION` 升 `ranking-v3`，同步 `src/retrieval-policy.json` 的 `rankingVersion`，新增 injection 阈值/预算字段。
- `src/retrieval.js`（或 indexer）：若无现成"列条目标题"能力，新增轻量 `listTitles({projectId, scope})`（只读扫描，不走向量）。
